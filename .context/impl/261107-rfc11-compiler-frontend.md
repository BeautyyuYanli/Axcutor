# RFC 11 编译器前端实现报告

Rust 编译器前端已实现五阶段静态分析、16 个 builtin 的静态契约、递归工作流依赖闭包、归一化 AST，以及画布变量补全和动态端口查询。实现范围止于静态编译与画布分析；运行期 builtin 求值和 Temporal 执行器属于后续后端工作。

调用方通过 `compile_workflow` 提供入口标识与 YAML/JSON 源文档快照，获得 `diagnostics`、`analysis` 和可选 `bundle`。资源标识按完整字符串匹配，由调用方提供依赖源；核心没有文件或网络 I/O。任一入口闭包错误都会使 bundle 为 null，诊断保留工作流、图路径、节点、边和参数地址。无法证明的定值事实不进入补全结果，独立且满足分析前提的图仍可保留结果。

`NormalizedAst` 是前端交付执行方的唯一模型。bundle 自包含入口及传递依赖，保存显式参数绑定、分支输出子集、catch 选择器、路由与 kill 集。模型保留默认值缺省与显式 null、单次迭代输出与汇聚集合的区别；内联图只接收捕获项和迭代注入项，私有变量不进入父图并发写集。

WASM 与 Python 模块 `axcutor_core` 共用同一 Rust 核心，以 JSON 文本提供编译、变量补全和端口查询。源文档语言错误进入诊断数组；非法请求或查询参数转换为宿主参数错误。数值保持精度及整数/浮点区别，映射保持插入顺序，普通对象不会因键名与序列化库标记相同而变成数字。消费者应保存原始工件文本，避免经 JavaScript Number 转换后重新发布。

每次编译独立拥有输入快照与分析状态，不保留全局缓存、解析器或宿主回调；返回工件拥有自身数据。递归调用消费预收集签名，不展开递归图体。查询复用完整图分析，无需重新编译，也不会重新证明调用方修改过的定值事实。

源值树与 expected TypeSpec 的深度上限为 128，GraphAnalysis 为固定模型外壳保留四层余量，上限为 132；成功编译的完整分析可经文本查询接口消费，超限参数返回宿主错误。YAML 接受与 JSON 数据模型匹配的七种标准标签，拒绝锚点、别名、自定义标签及非 JSON 扩展。

调用方式与完整契约见[接口说明](../../docs/compiler-api.md)，构建入口见[README](../../README.md)，设计依据见[定稿方案](../proposals/261107-rfc11-compiler-frontend.md)。
