- 依据 RFC-0012 与最终 spec，`run` 通过结构化配置选择执行器。
  - `builtin` 必须使用 `{executor: "builtin", content: "..."}`，拒绝裸字符串、空正文和额外配置字段；扩展执行器保留其配置、字段顺序与精确 JSON 数值。
  - 图变量、结构体属性及节点和分支标识符统一排除 Python 硬关键字；执行器名称遵循通用 `Identifier` 规则。

- 编译器仅依据显式输入契约确定数据依赖，向执行器提供语言无关的类型信息。
  - 不再扫描正文中的变量引用，也不再导出 `references`；归一化 AST 携带按输入声明顺序保存的 `input_schema`。
  - 每次尝试只取得声明输入的深拷贝快照；图状态仍由运行时栈帧持有，输出通过 Rust 契约校验后原子写回。

- 默认 `builtin` 在宿主进程执行可信异步 Python，并提供可独立编译和静态检查的强类型源码。
  - `execute(input)` 接收冻结的 `Input` 模型；嵌套结构体支持属性访问。业务代码返回 `Output(...)` 或 `Branch.<分支>(...)`，分支构造器仅接受该分支承诺的字段。
  - 输入 `number` 转为原生 `float`；输出接受有限 `float` 或合法 `int`，严格区分布尔与数值。输出可选属性保留“键省略”与“显式 null”的区别。
  - 源码合成保持内容字符与正文相对行号；输出契约违约归类为 `contract`，业务或语法故障归类为 `execution`。

- Worker 按执行器名称路由，并统一管理单次尝试的生命周期。
  - `create_worker(client, task_queue)` 默认提供 `builtin`，可选注册表接入扩展执行器；`options.task_queues` 以执行器名称为键。
  - 每次尝试创建独立模块命名空间，统一管理期限、心跳、取消信号和任务清理；超时或取消后的迟到结果不写入图状态。
  - Activity 与 Workflow 两处 Rust ABI 校验继续约束分支、字段子集及输出类型。
