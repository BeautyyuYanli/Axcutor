Playground 的流程画布使用从左到右排列的紧凑节点并持续显示，Trace 位于底部面板，以共享时间轴展示真实调用的父子关系、并行关系、状态和耗时，支持缩放、Fit，以及定位上方画布中的流程节点。点击调用可分别查看真实 Input、Output、返回分支、失败原因和等待、重试事件；精确起止时间默认折叠，快速步骤、循环调用及失败或取消前的记录均可在结束后继续查看。业务数据保留 JSON 数值精度与字段顺序。文件和编辑区收起后保留图标入口，保存与丢弃位于 Editor，Run 与 Cancel 位于运行配置行；Entry 展示模块名，画布来源自动选择。底部当前标签同时用于展开和收起，正常状态不另列说明，异常或清理阻塞仍有提示。

仅在 Playground 进程内存中保留当前或最近一轮及其工作流快照。刷新页面可恢复；下一轮通过预检并取得执行 ID 后替换上一轮，保存、编译或输入预检失败保留原记录。后端重启清空记录，不新增持久化存储或历史列表。后续编辑不会改变运行快照，恢复重试保留未保存编辑。

新增 `GET /v1/workspace/trace`，返回最近一轮的执行状态、源码快照与累计调用记录；无记录返回 `null`。携带 `execution_id` 时校验归属，记录被替换或清空则返回 `404`。Trace 观察和重试独立于执行终态与 workspace 清理，查询失败不会误报运行失败或阻止清理解锁。普通 Execution API 保持原契约，runtime 的可选 `record_trace` 默认关闭。

开始、结束和事件时间来自可重放的 Workflow 时钟；未结束调用延伸至实际观测时间，结束后固定。Temporal 原生 Activity 重试仅展示已知策略，不提供单次尝试指标。最终 trace 捕获前依赖常驻 Worker，捕获后由 Playground 内存提供查询。
