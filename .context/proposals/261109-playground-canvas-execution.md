# Playground 画布空间与执行展示

## 可收起的文件区和编辑区

在顶部提供 Workspace files 和 Editor 两个独立开关，默认展开，使用原生按钮表达展开状态；两个区域都收起时，开关仍然可见。文件区收起后移除其占用列，编辑区收起后把剩余空间交给画布；两者都收起时画布占满主工作区。

折叠仅改变界面可见性，保留当前文件、未保存内容、编辑位置、画布来源和执行观察。点击文件、新建成功或点击需要编辑源码的诊断时展开编辑区。恢复区域不重新加载或保存文件。改变区域尺寸后画布适配可用空间，继续支持缩放和作用域导航。

桌面和窄屏均按实际可见区域排版，不留下空列或空行。沿用现有最小样式，只补充区域开关、尺寸约束和必要的状态标记；不加入拖拽分栏、布局设置或偏好存储。

## 清晰的执行状态

执行面板标题处始终展示简短、可读的运行状态，面板收起时也能辨识。区分未运行、提交中、等待获取执行状态、运行中、取消中、成功、失败和已取消；共享 workspace 忙或执行后仍未解除编辑锁定时，另外解释当前不可编辑的原因。

执行状态来自现有提交、观察、取消和 workspace 状态。提交期间不把上次运行的成功结果当成本次结果；只获得执行 ID 或暂时查询失败时，明确仍在观察或重试，并保留取消能力。执行终态不等于文件已经可编辑，面板需保留相应提示。

运行中优先展示当前步骤。使用工作流和节点名称、并行项索引、等待信号提示表达正在发生的事情，准确等待地址保留在需要发信号的位置。后台轮询更新内容，不改变用户主动选择或收起的面板；不添加未由服务端提供的进度百分比、已完成节点历史或时间线。

## 面向实际数据的运行内容

运行面板按“状态摘要 → 当前步骤及所选步骤数据”组织。当前步骤保留必要的父子关系和独立选择入口，默认展示一个真实的当前步骤的数据；用户选择后显示该步骤的数据并与画布联动。数据按字段名和实际值展示，不同时展开每一帧的整块变量 JSON。

成功后以结果为主体，展示输出字段和值及实际返回分支；失败时突出失败原因，取消后明确展示已取消。执行 ID、开始与结束时间放入次要的原生 details，默认不挤占内容区域。空数据、等待数据和暂无结果有明确提示。

业务值继续从现有原始 JSON 切片读取，保留大整数、小数精度和字段顺序。使用已有 JsonText 按字段格式化即可，不增加通用 JSON 树组件或新的数据缓存。

## 移除编译内部展示

移除源码区的 Entry input contract 展示，以及画布下方的 Static probe、TypeSpec、Expected type、definite_in、injected、Derived ports 和 kill_vars 表格，不转移到高级模式或默认收起区。图中保留节点名称、分支、进入子图操作及选中和运行状态；去掉默认端口种类等内部标签，把必要的并行、重试和超时说明写成可读文字。

同步删除因此无调用方的组件参数、展示计算和样式。编译结果仍供现有图拓扑、诊断和执行快照使用；实际源码中的类型声明不受界面展示规则限制。编译错误、文件定位、运行输入及输出均保留。

## 实现边界

实现集中在 App、SourceWorkspace、CfgCanvas、ExecutionInspector、FrameTree 及必要的前端展示辅助代码和样式，更新现有 Playground 指南中受影响的说明。保留原生控件，不新增依赖。文件保存、revision、执行观察、取消与清理继续由现有 composable 和后端管理，不修改 HTTP 契约或生成文件。
