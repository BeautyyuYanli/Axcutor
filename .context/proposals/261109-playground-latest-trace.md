# Playground 最近一轮执行追踪

## 体验与保留范围

Playground 增加执行追踪时间线：一次 Run 对应一条 Trace，实际步骤调用在同一时间轴上以持续时间条展示，保留父子关系和并行关系。运行中持续更新；结束后仍可选择已结束步骤，查看实际输入、输出、状态、耗时、返回分支和失败原因。重试与等待信息仅在实际记录可提供时展示。

仅保留当前或最近一轮，不提供运行历史列表。新执行替换上一轮；未通过保存、编译或输入预检的尝试保留上一轮记录。提交结果不确定但已取得执行 ID 时观察该 ID，不能重复提交，也不能把上一轮数据混入新执行。

最近一轮记录由 Playground 进程在内存中管理，结束后持续可查；页面刷新可恢复本次后端启动期间的最近一轮及对应工作流快照。后端重启清空该记录。不新增数据库、文件归档、浏览器历史存储或外部可观测平台依赖。

## 真实执行记录

从实际运行边界记录开始、完成、失败或取消，避免依靠活跃帧轮询推测历史。短于轮询间隔的步骤也要完整出现；循环中重复经过同一节点、并行项和嵌套调用使用独立的调用标识，不能仅以节点名称或地址去重。

记录的输入和输出是对应调用真实使用及返回的数据，按现有无损 JSON 机制保留大整数、小数与字段顺序。输入、输出分别展示；尚未产生输出、失败和取消有明确说明。选择步骤后同时展示必要的状态和时间信息，不展示 TypeSpec 等编译内部数据。

时间来自运行记录，运行中的时间条持续延伸，结束后固定；未发生或未知的事件不伪造。正常结束、失败、取消和信号等待均保留已经发生的步骤。时间线与工作流快照对应，不受后续文件编辑影响。

## 时间线界面

沿用现有折叠文件区和编辑区的布局，在主画布区域提供流程图与执行追踪的切换。追踪视图采用共享时间刻度、层级步骤名称、状态标记和可选择的时间条，支持查看完整执行和缩放。选中步骤后在清晰的数据详情区查看 Input、Output 与有价值的运行信息，并保留与对应流程节点的定位能力。

最近一轮整体结果、失败原因、取消状态和 workspace 尚未解除只读的提示继续可见。轮询保留用户选择；新一轮、失效选择和页面恢复按当前 Trace 标识处理，避免旧响应覆盖新记录。窄屏使用区域内滚动，控件支持键盘操作。

## 实现边界

可以补充 runtime 的执行观测记录与查询能力，以及 Playground 专用的最近一轮查询接口；保持普通 Execution API 和通用 host 的无记录缓存职责。追踪不得改变执行结果、并发、重试、取消或清理行为，普通运行无需承担不必要的追踪开销。

复用现有 Temporal、WASM、Vue、原生控件及 JSON 工具，不增加追踪服务或 UI 依赖。协议变更修改 OpenAPI 源并通过现有生成命令更新客户端，不手工修改生成文件。同步现有 Playground 文档，明确最近一轮的保留范围和后端重启语义。
