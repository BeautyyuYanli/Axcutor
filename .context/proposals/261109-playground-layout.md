# Playground 工作台布局

## 目标与布局

将 Playground 整理为以源码编辑和控制流检查为中心的网页工作台。当前文件树、配置和编辑器共享一列，CFG 与执行详情持续占据其余列，默认字号、间距与长内容又缺少约束，导致主要工作区域狭窄、操作分散。

桌面采用以下结构：

```text
应用栏：Axcutor Playground · 保存状态 · Save files / Reload · Run / Cancel
运行配置：Entry · Input file · Canvas source · 编译状态
┌────────────┬────────────────────┬────────────────────┐
│ 文件侧栏   │ 源码编辑区         │ 控制流图区         │
│ 目录与文件 │ 当前文件路径与状态 │ 作用域导航与 CFG   │
│ 新建文件   │ 可用高度内编辑     │ 所选节点的静态探针 │
└────────────┴────────────────────┴────────────────────┘
底部面板：Execution · Diagnostics（数量）· 展开 / 收起
```

文件侧栏保持紧凑，源码与 CFG 平分主要宽度。桌面工作台利用视口高度，文件列表、编辑器、图分析与底部输出在各自区域内滚动，顶部操作和当前文件路径保持可见。底部面板收起时仅占标题行，展开时使用有上限的高度，给编辑与图预览保留主要空间。

中等宽度下适当缩小侧栏，空间不足时源码与 CFG 改为上下排列；手机宽度下文件、源码、CFG 和底部面板依次排列，使用页面滚动。长路径、表格和原始 JSON 不撑宽页面。

## 文件与源码

将文件浏览和源码编辑拆为明确的界面区域。文件侧栏展示层级、完整路径提示、清晰的当前文件选中状态，以及独立的新建文件表单。当前选中文件始终使用现有相对路径作为标识。

源码区顶部展示当前文件路径、生成文件或运行期间只读状态，以及当前文件的删除操作。文本区使用等宽字体、适宜的字号与行高，填满剩余空间；保留原生 textarea 和浏览器的文本选择、复制、撤销及键盘操作。入口字段契约使用原生 details 收纳，避免长期挤占编辑空间。

保存、重载和执行按钮集中在应用栏；入口、输入文件和画布来源集中在运行配置行。保存状态、编译状态与写入锁定原因有稳定的位置，使用文字表达，不依赖颜色。

## CFG、执行与诊断

CFG 区顶部保留工作流选择、作用域面包屑与 Fit graph。画布占据主要区域；静态节点探针置于下方可滚动的区域，未选择节点时仅展示简短提示，选中后展示现有类型、变量与端口信息。选中节点需要与运行中的节点有可区分的视觉标记。

执行详情和诊断共用底部面板，通过两个原生按钮切换，按钮展示当前选择状态并支持键盘操作；提供明确的展开与收起操作。Execution 保留状态、帧树、结果与失败详情；Diagnostics 保留错误和源码定位。切换或收起只改变可见性，不销毁执行观察或编译状态。

提交运行时展开 Execution，方便观察状态；新的编译问题或明确的提交失败展开 Diagnostics，使错误可见。提交结果不确定且已获得 execution ID 时继续展示执行观察与取消能力。后台状态轮询不会反复切换用户正在查看的面板。

## 必要样式与实现边界

使用系统界面字体、等宽源码字体、统一的基础字号与间距、浅色区域底色、细分隔线、必要的选中和焦点样式。原生按钮、select、details、textarea 保留其交互语义；Run 作为主要操作获得适度强调。样式服务于空间分配和信息层级，不加入图片、图标库、动画主题或 UI 组件库。

调整 App.vue、SourceWorkspace.vue 及必要的源码编辑组件、CFG、执行与诊断组件和 style.css；同步现有 Playground 指南中相关界面说明。布局使用 Grid/Flex 和少量组件内可见性状态，不加入拖拽分栏、布局配置、浏览器偏好持久化或新的业务状态层。

文件、revision、提交快照、执行观察与清理的所有权继续由现有 composable 和后端管理。已有保存冲突保护、提交及执行期间只读、执行取消、CFG 与帧联动、实时编译与无损 JSON 展示均沿用现有接口与数据模型。生成客户端、OpenAPI 与 WASM 不需要协议改动。
