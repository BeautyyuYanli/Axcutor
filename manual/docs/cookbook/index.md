# 实战组合配方（Cookbook）

Axcutor 的设计哲学并非为每种业务场景堆叠专用语法糖，而是提供一组彼此正交的底层执行原语——有状态控制流图（CFG）、单入口单出口（SESE）内联子图（`Block Frame`）、集合迭代修饰符（`for_each`）、零开销内建算子（`builtin:*`）以及声明式容错契约（`timeout_ms`、`retry`、`catch`）。

在工程实践中，将复杂业务逻辑拆解并映射为上述原语的正交组合，关键在于把握以下三个维度的架构权衡。

---

## 迭代范式权衡：有状态成环回边 vs. 无状态 `for_each`

面对重复执行或集合遍历需求，首要决策是辨析迭代轮次之间是否存在**状态耦合**与**提前终止（短路）**诉求：

- **有状态成环回边（CFG Loop）**：适用于跨轮次存在上下文依赖或迭代次数动态决定的场景（如携带前序报错反馈的自修正闭环、按优先级尝试并命中即刻早退的回退链、串行累积全局状态的折叠计算）。此类模式依赖 `graph.variables` 维护跨轮状态，配合 `builtin:array_shift`（通过 `.some` / `.empty` 分支消费队列）、`builtin:array_append` 与 `builtin:math` 按写时复制（Copy-on-Write）不可变语义推进队列与累积状态，并通过指向前序节点的 CFG 回边实现精确的步进控制。
- **无状态集合映射（`for_each`）**：适用于元素间完全独立、无需感知彼此执行进度或中间结果的同构批处理场景。运行时为每个元素分配相互隔离的输入上下文，支持通过 `concurrency` 声明并发度上限，并在所有元素处理完毕后按原始输入顺序确定性地汇聚输出集合。
- **正交嵌套（外层并发映射 + 内层状态机）**：当集合元素彼此独立、但单个元素内部需要运行多步分支或动态循环时，应将 `for_each` 挂载于 SESE 内联 `graph` 节点之上。外层利用 `for_each` 实现元素级并发扇出与保序收集，内层借助每次迭代独立派生的 `Block Frame` 封装局部循环状态，避免跨元素的状态污染。

## 零开销数据流转：内建纯函数算子与分支关联输出

在编排多步骤与多分支工作流时，应避免为单纯的数据整形、默认回退或字段透传引入外部执行器调用，同时严防未命中分支污染全局上下文：

- **内建算子（`builtin:*`）确定性变换**：对于可空参数拆包（`builtin:unwrap`）、常量注入与字段重映射（`builtin:assign`）、条件与算术运算（`builtin:compare` / `builtin:logic` / `builtin:math`）、队列首尾操作（`builtin:array_shift` / `builtin:array_append`）以及二维结果展平（`builtin:array_flatten`），应直接采用运行时原生支持的零开销纯函数算子，在当前栈帧内完成同步状态变换与确定性路由（如 `.some` / `.none`、`.empty`）。
- **分支关联输出（`branches.<choice>.output`）**：在条件分支或内联子图的多出口汇聚处，不同路径往往产出异构的数据子集。通过显式将 `output` 子集绑定在具体的 `branches.<choice>` 下，仅当该分支实际命中时才向父级栈帧写回对应字段；对于在 `for_each` 过滤中被剔除的分支（或 `catch` 降级分支），直接省略对应变量的产出，即可在汇聚阶段由 `for_each` 自动跳过未产出该变量的元素，无需额外编写后置过滤逻辑。

## 事务与异常边界设计：SESE 块级帧、主动中止与降级补偿

构建生产级高可用工作流，需要明确划定“状态回滚半径”与“异常捕获粒度”，将业务校验不通过与底层基础设施故障纳入统一的容错模型：

- **多步原子事务边界（SESE `Block Frame`）**：将需要保证原子性的串联步骤封装进内联 `graph` 节点。子图执行期间的所有变量写入均驻留在独立的 `Block Frame` 中；仅当子图正常抵达 `-> end`（或 `-> end.<branch>`）时，其声明的 `output` 才会原子性地提交至父图。若任一步骤触发超时、未捕获异常或通过条件路由显式跳转至 `-> fail`，整个 `Block Frame` 将直接销毁并丢弃未提交修改，实现子图内存状态的原子回滚。
- **超时、重试与补偿的正交分层**：`timeout_ms`、`retry` 与 `catch` 可按需挂载于单步节点、SESE 内联子图或 `for_each` 节点之上：
  - 挂载于**内联子图**时，内部步骤异常或 `-> fail` 触发整块状态回滚后，由外层 `catch` 捕获并路由至外部业务补偿节点，完成已发生外部 I/O 副作用的业务冲正；
  - 挂载于 **`for_each` 内联子图**时，容错边界下沉至**单元素粒度**——单个元素的超时与重试仅在当前元素内部闭环，耗尽重试或触发失败后进入该元素专属的 `catch` 分支（如利用 `builtin:assign` 零拷贝透传原元素至死信队列输出变量），从而确保单点异常数据不会阻断整批任务的并发推进。
