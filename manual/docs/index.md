# Axcutor 用户文档（User Documentation）

Axcutor 用户文档面向工作流编写者、业务集成开发者与自动化 Agent，聚焦如何使用 YAML/JSON 声明类型安全、并发无竞争且具备事务回滚能力的工作流。

---

## 核心设计原则

1. **统一节点模型（Unified Node Model）**：
   取消顶层包装壳，每个工作流文件本身就是一个根节点（`input` / `output` / `branches`）。图内子节点支持三种对等形态：原子业务动作（`run`）、跨文件/内建调用（`use`）与内联块级子图（`graph`）。
2. **闭合静态强类型与全路径必达定值**：
   所有输入输出均采用闭合 JSON Schema 子集（`TypeSpec`），配合排他分支按需产出契约（`branches.<choice>.output`），在编译期静态验证每一条可达路径上的变量定值状态，消除 `null` 占位初值与未初始化读取。
3. **结构化并发与无锁确定性**：
   同构集合遍历（`for_each`）与异构并发组（`-> [a, b] ->`）均遵循单入口单出口（SESE）约束。运行时通过 Fork 只读快照与编译期写集合两两互斥检查，在无锁条件下保证并发执行结果的确定性。
4. **栈帧级异常捕获与原子回滚**：
   超时（`timeout_ms`）、快照重试（`retry`）、异常分支物化（`catch`）与子图主动回滚（`-> fail`）直接融入控制流图，确保失败尝试或中止的子图不会向父栈帧泄漏半成品状态。
