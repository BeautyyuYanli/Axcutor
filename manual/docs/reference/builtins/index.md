# 运行时内建算子通用约定（`builtin:*`）

Axcutor 运行时内置了一组零外部进程开销、确定性、常数时间复杂度的原生泛型算子，涵盖值绑定、可空拆包、分支路由、逻辑与算术运算以及集合与结构体操作。所有内建算子统一通过 **`use: builtin:<op>`** 配合 **`with`** 块调用，共享一致的参数绑定、类型校验、控制流与运行期执行契约。

---

## 一、 调用语法与显式参数绑定

内建算子与外部子图调用保持统一的声明形态，通过 `use: builtin:<op>` 指定算子名称，并在 `with.input` 与 `with.output` 中显式完成数据绑定：

1. **必填参数显式声明**：所有必填的 `with.input` 与 `with.output` 参数均必须显式写出，不支持隐式同名省略。
2. **输入绑定（`with.input`）**：每个输入参数可绑定以下三种数据来源之一：
   * **图内顶层变量**：直接填写已定值的变量名（如 `source: raw_text`）。
   * **结构体字段路径**：通过点号路径读取非空 `TypedDict` 变量的子字段（如 `source: ticket.operator_override`）。
   * **内联常量字面量**：使用 `{ value: <literal> }` 显式包装 JSON 字面量（如 `default: { value: "auto_bot" }` 或 `op: { value: "eq" }`），避免与变量名混淆。
3. **输出绑定（`with.output`）**：每个输出参数必须绑定到当前图内已声明类型的**顶层变量名**（不支持直接写入结构体子字段路径 `a.b`；如需更新结构体字段，应使用结构体重组算子生成新结构体后整体赋回顶层变量）。

```yaml
nodes:
  resolve_operator:
    use: builtin:unwrap
    with:
      input:
        source: ticket.operator_override
        default: { value: "auto_bot" }
      output:
        value: assigned_operator
```

## 二、 显式类型声明与单向子类型兼容

内建算子多为泛型算子，不在节点自身重复声明完整的 JSON Schema，而是依托所在图的变量类型声明进行编译期静态类型推导与校验：

1. **目标变量须预先声明类型**：`with.output` 绑定的所有目标变量，必须在当前图的作用域内预先声明明确的类型（`TypeSpec`），声明位置可以是：
   * 当前工作流或内联子图的 `output` 契约；
   * 当前图的局部状态变量表 `graph.variables`；
   * 同一图内其他未挂载 `for_each` 的 `run` 或 `graph` 节点的 `output` 契约。
2. **单向子类型兼容（`<:`）**：编译器在静态检查阶段校验 `with.input` 实参类型与算子期望类型、以及算子产出类型与 `with.output` 目标变量声明类型之间满足**单向子类型兼容**：
   * **非空向可空提升**：非空类型 `T` 可直接赋给可空目标类型 `[T, "null"]`（反之则必须经过拆包算子显式收窄）。
   * **数值拓宽与枚举收敛**：`integer` 可赋给 `number`；带 `enum` 约束的子集字面量类型可赋给同基础类型的宽泛类型。
   * **容器与结构体协变**：`Array<T>`、`OrderedMap<string, V>` 与 `TypedDict` 字段支持按元素或字段类型协变传递（例如非空元素列表可直接写入声明为可空元素列表的目标变量）。

## 三、 控制流形态与反定值（Kill）安全保护

根据算子语义与参数配置（如是否显式声明 `with.output` 或是否提供回退参数 `default`），内建算子在控制流图（CFG）中表现为以下两类形态之一：

| 控制流形态 | 出边连接规则 | 定值与流敏感状态演进 |
| :--- | :--- | :--- |
| **无分支单出边** | 在 `edges` 中直接使用节点名 `N -> Next` 连接后继节点（禁止挂载 `.branch` 后缀）。 | 算子执行完毕后必然成功定值 `with.output` 中的所有目标变量，后继节点可安全读取。 |
| **排他条件分支** | 在 `edges` 中必须通过 `N.<branch> -> Next` 显式穷尽所有分支出边（禁止使用无后缀的裸节点名 `N` 作为源点）。 | • **布尔与多路分支**（`.true` / `.false` / `.<enum_val>`）：纯控制流路由，不产生输出变量。<br>• **带值拆包/查找/运算分支**（`.some` / `.none` 或 `.some` / `.empty`）：仅在命中分支（`.some`）定值目标变量；在未命中或异常分支（`.none` / `.empty`）触发**反定值（Kill）保护**。 |

### 反定值（Kill）与防脏读机制

在循环体或多路径汇合图中，一个输出目标变量可能在上一轮迭代或前序路径中已经被赋予过旧值。当算子暴露 `.some` / `.none`（或 `.some` / `.empty`）排他分支且运行期走向 **`.none`** 或 **`.empty`** 分支时：

* **运行期强制解绑**：运行时会主动从当前帧状态中**移除（Unbind）**该算子目标输出变量的旧绑定，将其重置为“未绑定（Unbound）”状态，而非保留上一轮遗留的脏值。
* **编译期流敏感拦截**：静态数据流分析会在 `.none` / `.empty` 出边上将该目标变量从“必已定值集合”中剔除。若后继节点在未重新赋值的情况下尝试读取该变量，编译器将直接报错拦截。
* **输入输出同名安全约束**：对于暴露 `.none` 分支的算子，其 `with.output` 目标变量禁止与 `with.input` 输入源根变量同名，以防在 `.none` 分支上因反定值机制意外抹除原输入变量。

## 四、 运行期语义与使用限制

1. **计步规则与环路防死锁**：每次激活执行 `use: builtin:<op>` 节点均计 **`1` 步**，计入所在图实例的累计步数并与 `graph.max_steps` 预算对比。这确保了完全由内建算子构成的循环图同样受最大步数护栏保护，不会发生无限死循环。
2. **写时复制（Copy-on-Write）与不可变值语义**：所有涉及列表、有序映射或结构体的内建算子均遵循纯函数式不可变更新——始终构造并返回新的集合或结构体副本，**绝不原地修改（Mutate）**输入变量中的既有对象引用。因此在无 `.none` 分支的更新算子中，允许将 `with.output.result` 与 `with.input.source` 绑定为同一个顶层变量名以实现安全的滚动状态更新。
3. **禁用的节点修饰符**：内建算子属于确定性内存级瞬时操作，所有 `builtin:*` 节点**一律禁止声明 `for_each`、`timeout_ms`、`retry` 或 `catch`**。
4. **并发组顶层成员限制**：在边定义中使用并发组语法 `[worker_a, worker_b]` 时，**只有表现为“无分支单出边”的内建算子才可直接作为并发组的顶层成员**；任何暴露排他控制分支（如 `.true` / `.false`、`.some` / `.none`、`.some` / `.empty` 或枚举分支）的内建算子均不可直接放入并发组顶层（若需在并发分支内部执行条件路由或拆包，应将其封装在内联 `graph` 子图节点内）。
